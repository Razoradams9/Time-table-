## Decisions
1. Lab detection = `is_double`. Course `is_lab` = any of its entries is_double; lab periods = double rows, lecture periods = non-double rows.
2. Workload `net_hours_in_range = scheduled_hours_in_range - given_up - uncovered + substituted` (uncovered hours are not taught either; equals the spec formula while there are no UNCOVERED rows). Scheduled-in-range sums the base hours of every Mon-Sat date in [start,end] (so partial weeks are exact), not whole weeks.
3. Workload page = a "Workload" tab on the Reports page (Fairness.jsx, seg toggle) via a reusable `WorkloadPanel` component; teachers get a "My teaching hours" card on the Dashboard (all roles) using the same endpoint with their own id.
4. Courses endpoint is readable by every logged-in user (matches the open timetable view endpoints); `teacher_id` is an optional filter.
5. Compensation: one record per substituted period; a lab block yields ONE record with `periods=2` (consecutive pair) and falls back to TWO single records only if no consecutive pair exists in the horizon. Only the ABSENT teacher owes (co-teacher does not).
6. Horizon: anchor week = week of max(missed_date, today); weeks offset 0, 1, 2; candidate dates must be > missed_date, >= today, Mon-Sat. Manual picks (confirm/reschedule) use the same checks but no horizon cap.
7. Teacher on ANY active leave on a date (full or partial) makes that date unusable for that teacher (conservative). Classes have no leaves, so the "class" half of that rule is satisfied by the class-occupancy check.
8. Ranking key: `(week_offset, date, teacher_periods_that_day, 0 if adjacent-to-existing-class and load_after<=max_consecutive else 1, period_index)`.
9. Authority: confirm / reschedule / mark-done / suggestions / repropose = HOD or owning teacher; cancel / backfill = HOD only. Invalid slot -> HTTP 409 with reason. Mark-done only when proposed (last) date <= today.
10. Auto-sweep (run at the start of list/summary): SCHEDULED whose last date < today -> COMPLETED ("Auto-completed"); PROPOSED with null/past date -> re-propose.
11. Notifications are aggregated (one per teacher + one per HOD per operation) to avoid spam; audit actions are `COMP_PROPOSED / COMP_SCHEDULED / COMP_RESCHEDULED / COMP_COMPLETED / COMP_CANCELLED / COMP_BACKFILL`, entity `compensation`.
12. Substitution engine must treat PROPOSED/SCHEDULED make-up slots as busy for the substitute (small edit in `_busy_slots_from_subs`, lazy import to avoid a cycle) so a make-up is never double-booked by a later substitution.
13. Adjusted timetable shows PROPOSED/SCHEDULED/COMPLETED make-ups from a read-only, all-user endpoint `GET /api/compensations/calendar?on=`; PROPOSED rendered with a dashed "proposed" variant, tag `MAKE-UP`.
